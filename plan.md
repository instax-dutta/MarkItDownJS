# MarkItDownJS Implementation Plan

## Overview

This document outlines the implementation plan for improving package adoption, repo visibility, and developer experience for the MarkItDownJS monorepo.

**Monorepo:** pnpm workspace with 20 packages under `packages/`
**npm scope:** `@markitdownjs/*`
**Current stats:** 1 star, 0 forks, ~217 weekly downloads on core, 6 open issues, issue creation restricted.

## Key Discrepancies Found (Must Resolve Before Execution)

Before starting, the following gaps between the execution document and the actual codebase must be addressed:

| # | Issue | Impact | Resolution |
|---|-------|--------|------------|
| D1 | `registerConverter()`, `registerRenderer()`, `registerChunker()` don't exist on `MarkItDown` | `@markitdownjs/all` `preset.ts` and README examples won't work | Add convenience methods to `MarkItDown` class |
| D2 | Chunks are NOT auto-generated by `convert()` | Execution doc assumes `result.chunks` is populated automatically | Add auto-chunking to `convert()` when chunkers are registered |
| D3 | `detectMimeTypeFromData()` only detects PDF/ZIP/PNG/JPEG/WebP/GIF | Missing DOCX/XLSX/PPTX (all ZIP), XML, HTML, EPUB, BMP, TIFF, etc. | Extend magic-byte detection to cover all supported formats |
| D4 | `normalizeInput()` in parser.ts doesn't extract fileName from string paths | `convert({ source: "file.pdf" })` won't auto-detect MIME | Update `normalizeInput()` to parse extension from string paths |
| D5 | Chunking package exports `DocumentChunker` + strategies, not `HeadingChunker`/`TokenChunker` | Execution doc references non-existent class names | Use actual class names in re-exports |

## Phase 1: Core Foundation (Tasks 1.1, 1.2, 1.3 combined)

### Step 1.1 — Add convenience methods to `MarkItDown` parser

**File:** `packages/core/src/parser.ts`

Add three new methods to the `MarkItDown` class:

```typescript
registerConverter(converter: Converter): void {
  this.getRegistry().register(converter);
}

registerRenderer(renderer: MarkdownRenderer | HtmlRenderer | JsonRenderer | PlainTextRenderer): void {
  // Store internally; use in convert() when no explicit renderer passed
}

registerChunker(chunker: DocumentChunker): void {
  // Store internally; auto-run after convert() if chunking enabled
}
```

Also update `convert()` to:
1. Auto-detect MIME from `fileName` (extension) when `mimeType` is omitted
2. Auto-detect MIME from buffer magic bytes when `mimeType` is omitted
3. Auto-chunk the result if registered chunkers exist and `options.chunking` is set (or defaults)
4. Return chunks in the `ConversionResult` when auto-chunking is enabled

### Step 1.2 — Extend `detectMimeTypeFromData()` in shared

**File:** `packages/shared/src/utils.ts`

Add magic-byte detection for all missing formats:
- `PK` (ZIP) docx/xlsx/pptx → needs content-type XML inside to differentiate
- `<?xml` or `<htm` → XML/HTML
- `PK` + check internal `[Content_Types].xml` → docx/xlsx/pptx
- EPUB magic bytes
- BMP, TIFF signatures

Also export a new `detectMimeType(buffer, fileName?)` function that combines:
1. Magic byte detection from buffer
2. Extension-based detection from fileName (fallback)

### Step 1.3 — Update `normalizeInput()` in parser.ts

When `source` is a string:
- Extract `fileName` from the path (last segment after `/` or `\`)
- Infer `mimeType` from extension if not provided

When `source` is `Buffer`/`Uint8Array` and `mimeType` is absent:
- Call `detectMimeTypeFromData(buffer, fileName)` to auto-detect

### Step 1.4 — Create `packages/all/`

Create the following files:

- `packages/all/package.json` — dependencies on all 16+ packages, version 0.4.0
- `packages/all/tsconfig.json` — extends root tsconfig.base.json pattern
- `packages/all/src/index.ts` — re-exports MarkItDown, all converters, renderers, chunkers, types
- `packages/all/src/preset.ts` — `createMarkItDown()` factory using the new `registerConverter()`/`registerRenderer()`/`registerChunker()` convenience methods

### Step 1.5 — Create `packages/markitdownjs/` (unscoped)

- `packages/markitdownjs/package.json` — name `markitdownjs`, depends on `@markitdownjs/all`
- `packages/markitdownjs/src/index.ts` — `export * from "@markitdownjs/all"`

### Step 1.6 — Add `all` and `markitdownjs` to build config

- Add tsconfig entries for the new packages (following the existing pattern)
- Ensure `pnpm-workspace.yaml` covers them (it uses `packages/*` glob, so it should)
- Verify `pnpm build` succeeds for both new packages

**Deliverable:** `npm install markitdownjs` works; `createMarkItDown()` returns a fully configured instance with auto-detection.

## Key Risks

1. **pdfjs-dist ^5.x upgrade** — may have breaking API changes requiring more than version bump
2. **Magic-byte detection completeness** — distinguishing ZIP-based formats (docx vs xlsx vs pptx) requires reading internal `[Content_Types].xml` from the ZIP, which adds complexity
3. **Auto-chunking in `convert()`** — changes the semantics of `ConversionResult` and may affect existing consumers
4. **`registerConverter()`/`registerRenderer()`/`registerChunker()` additions** — these are new public API methods that need tests and documentation
